# 1.6.0

How to install it: [How to update](README.md#how-to-update). Coming from 1.5.0
(or 1.4.0, 1.3.0), the small `homelib-update.zip` is enough: 1.6.0 uses exactly
the same bundled Python packages.

## What's new

### Your videos in Jellyfin, with their real names

If you also run [Jellyfin](https://jellyfin.org) on the server (for example to
watch on a TV that isn't on Tailscale), it can now show your downloads properly:

- **Real titles, channel names and pictures.** Next to each video the app now
  saves a small `.nfo` file (title, channel, description, length) and a `.jpg`
  (the same thumbnail the app shows). Jellyfin reads both, so instead of
  `dQw4w9WgXcQ` you see the video's title with its picture.
- **No Shorts in Jellyfin.** Shorts now go in their own folder,
  `<library>/shorts/`, which tells Jellyfin to skip it. Only normal videos
  show up there. Shorts work in the app exactly as before.
- Deleting a video in the app (or the auto-delete) also removes its `.nfo` and
  `.jpg`, and it disappears from Jellyfin at its next scan.

Jellyfin only reads the files; it never downloads or deletes anything. The app
is still the only place where videos come and go. Music isn't affected.

## After updating

- On its first start the app moves the Shorts you already have into
  `shorts/` and writes the files for the videos you already have. It takes a
  second or two and needs nothing from you.
- **If you use Jellyfin:** open it in a browser, go to **Dashboard →
  Libraries** and click **Scan All Libraries**. The Shorts disappear and the
  other videos get their names. Nothing else needs to change.
- **Setting up Jellyfin for the first time** (not needed for the app itself):
  1. Install it on the server and let it read the videos:
     ```bash
     curl -fsSL https://repo.jellyfin.org/install-debuntu.sh | sudo bash
     sudo usermod -aG homelib jellyfin
     sudo systemctl restart jellyfin
     ```
  2. Open `http://<server's LAN IP>:8096`, create a user, then **Add Media
     Library**: content type **Home videos and photos**, folder
     `/var/lib/homelib/library` (or your `[library] dir`). Turn the metadata
     downloaders off: the `.nfo` files already have everything.
  3. In the Jellyfin app on the TV, enter `http://<server's LAN IP>:8096`.

  Jellyfin has its own login and listens on your home network on port 8096.
  This app stays as it was: only on `127.0.0.1` behind `tailscale serve`.
- Old behaviour that stays: video files are still `<id>.mp4`, normal videos
  still sit directly in the library folder, and the app plays everything from
  wherever it is. Nothing changes on the phones.
- **Going back to 1.5.0** (see [Going back](README.md#going-back)): if you also restore the database backup, move the
  Shorts back first, or they won't play:
  ```bash
  sudo -u homelib sh -c 'mv /var/lib/homelib/library/shorts/*.mp4 /var/lib/homelib/library/'
  ```
  Without restoring the database, 1.5.0 plays them from `shorts/` as is. The
  extra `.nfo`/`.jpg` files are harmless to 1.5.0.

**Small package works** (from 1.5.0, 1.4.0 or 1.3.0): no bundled Python package

## Design notes

- **Module.** `homelib/jellyfin.py`. Everything in it is best-effort: errors
  are logged, never raised into a download, delete or start-up.
- **Shorts folder.** `place(path, short, library_dir)` moves a finished video
  into `library/shorts/` when it's a Short (and back out if it's no longer
  one), with `os.replace` (same filesystem, instant). The downloader calls it
  right after the download, before `file_path` is stored, so the thumbnail
  frame, streaming and deletes all use the new path. The folder holds an
  **empty** `.ignore`: Jellyfin skips a folder with an empty `.ignore`, but
  reads any text in it as gitignore patterns (a non-empty one didn't hide
  anything in testing), so `shorts_dir()` empties it if it isn't empty.
- **`.nfo`.** Root `<movie>` with `title`, `plot` (the stored description),
  `studio` (channel), `runtime` (minutes), `dateadded` (download time, UTC),
  `uniqueid type="youtube"` and `tag` YouTube, built with ElementTree (so `&`
  and `<` in titles are escaped). A "Home videos and photos" library read
  `movie`, `musicvideo`, `episodedetails` and `video` roots alike;
  `movie` also works in a Movies library. Written via a dot-named temp file
  and `os.replace`, so Jellyfin never reads half a file.
- **`.jpg`.** A copy of `thumbs/<id>.jpg` (320 px, from YouTube or a frame).
  Jellyfin uses `<id>.jpg` beside the video as its cover; `<id>-thumb.jpg`
  would only be a secondary image. Only JPG thumbnails are copied (mock mode's
  SVGs aren't).
- **Late `.nfo`.** Jellyfin ignores an `.nfo` that appears after it first
  listed a video, on a normal scan and even on "Replace all metadata", but
  reads it once the video's modified time changes. `write_sidecars()`
  therefore touches the video (`os.utime`) after writing. This matters both
  for upgraded servers and for a new download that Jellyfin's real-time
  monitor sees before the `.nfo` exists.
- **Start-up sync.** `create_app()` calls `jellyfin.sync()`: for each ready
  video row, move it if it's in the wrong folder (updating `file_path`) and
  write the files if the `.nfo` is missing, or the `.jpg` is missing but a
  thumbnail exists. A second run does nothing.
- **Deletes.** `library.delete_video()` removes `<id>.nfo` and `<id>.jpg`
  beside the file. `disk_status()` counts `library/*.mp4` and
  `library/shorts/*.mp4`.
- **Not touched.** Music (`library/music/`, `media='audio'`), captions
  (`library/subs/`), `.partial`, the API, the database schema, the config file.
- **Tested** against the official `jellyfin/jellyfin` Docker image (server
  12.4.0) with a "Home videos and photos" library: titles, channel (as
  studio), cover from `<id>.jpg`, Shorts hidden (also when they were already
  listed before the move), deleted videos gone after a scan, and an upgraded
  video that Jellyfin had listed under its id renamed after a normal scan.
  Tests: `backend/tests/test_jellyfin.py`.
