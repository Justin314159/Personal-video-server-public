# 1.4.0

How to install it: [How to update](0-how-to-update.md). Coming from 1.3.0,
the small `homelib-update.zip` (under 1 MB) is enough: 1.4.0 uses exactly the
same Python packages.

## What's new

### Your downloads are just yours

- What you download from your profile ("My queue" or "Just download") only
  shows up for you: in Library, Downloads and search. The other profile
  doesn't see it.
- It's auto-deleted once **you** have watched it. It doesn't wait for the other
  person.
- **Share with both of us** makes a video both of yours. It shows up for both
  of you, goes in the Shared queue, and from then on it's only deleted once
  you've both watched it. You can share:
  - when downloading: it's the third option in the download sheet. It's
    preselected only when you download from **For you → Both of us**;
  - later, from a video's **⋯** menu in Library, or the **Share with both of
    us** button under the player.
- Private videos show **Just you** under the title in Library.
- If you both download the same video yourselves, it becomes both of yours.
- Sharing is one-way. There is no "make private again".

### Playlists

- New playlists start as **Just for me** (as before). A personal playlist now has
  a **Share with both of us** button: the other person sees it and can add to
  it, and its videos become shared videos.
- Videos in any playlist are still never auto-deleted.
- You can only add videos you can see, so the other person can't put your
  private videos in a shared playlist.

### Reload For you

- **For you** has a reload button (top right). A reload sets aside everything
  the feed was showing and brings a completely new batch. You won't see those
  earlier suggestions again for 30 days.
- "Just me" and "Both of us" each reload separately: the button reloads the one
  you're looking at.
- The 03:30 nightly run now does the same full reload, so each morning's feed is
  all new too.
- Each reload searches a bit deeper and mixes up your topics, so tapping it
  several times in a row still finds new videos. If it says **No new
  suggestions right now**, everything the searches found was shown recently:
  search and watch a few new things, add starter topics in **Your algorithm**,
  or try again tomorrow.
- If the server has no internet, a reload keeps the current feed instead of
  emptying it.

### Copy transcript

- The transcript panel (player → **Transcript**) has a **Copy** button. It copies
  the whole transcript as plain text: no timestamps, a new paragraph at each
  pause, repeated lines dropped. Ready to paste into Notes or a message.

### Small update packages

- Each release now also comes as `homelib-update.zip`: just the app, scripts
  and docs (under 1 MB instead of ~100 MB). It reuses the Python packages
  already on your server, after checking they're the versions it needs. If
  they aren't, it stops without changing anything and you use the full
  `homelib-usb.zip` as before. See [How to update](0-how-to-update.md).
- Fixed: the automatic backup that `update.sh` takes before updating always
  failed ("Permission denied", then "backup failed, continuing") when the
  package had been unpacked with `python3 -m zipfile`, as the docs say to.
  The daily 04:15 backups were not affected.

### Profile photos

- **Settings** → tap your picture (the small camera) → pick a photo. It's
  cropped to a square and shrunk on the phone, then shown everywhere your
  initial used to be. Tap it again to choose another or remove it.
- Photos are stored on the server in `/var/lib/homelib/avatars/` and are now
  part of the daily backup.

## After updating

- Nothing to do. The database is upgraded automatically.
- Videos already on the server keep their old setting: "My queue" downloads were
  already private; older **"Just download"** videos stay visible to both of you.
- Music is unchanged: the Music page is still one shared collection.
- This is privacy inside the app, not security. There are still no passwords,
  and anyone on your Tailscale network can reach the whole server.

## Design notes

- **A reload replaces the whole feed.** Every `GET /api/foryou` remembers what
  it showed. A reload (`POST /api/foryou/refresh?mode=me|both`, or the 03:30
  run) moves those ids into the new `reco_seen` table for 30 days, re-runs the
  candidate searches with rotated topics and 10 more results per search each
  time (20 → 50, then round again), and replaces the profile's pool with what
  came back. If every search fails, the old pool stays.
- **Visibility = the existing `audience` rule.** `library.relevant_profiles()`
  (who must watch before auto-delete) now also decides who sees a video:
  `/api/library`, `/api/downloads`, search's `local_status` and playlist adds
  use it. New downloads get `audience = p:<you>` unless they go to the Shared
  queue. `POST /api/videos/<id>/share` sets it to everyone and adds the video to
  the Shared queue. `PATCH /api/playlists/<id>` with `{"scope": "shared"}`
  shares a playlist.
- **Profile photos are resized on the phone** (canvas, 256 px JPEG), so the
  server needs no imaging library and the offline USB package no new
  dependency. `PUT /api/profiles/<id>/avatar` takes a data URL; the server
  checks size (≤ 2 MB) and that it's a JPEG/PNG/WebP. Profiles now carry
  `avatar: "/api/profiles/<id>/avatar?v=<time>"`. New column `profiles.avatar_at`.
- **Copy transcript** uses the clipboard API with a hidden-textarea fallback
  for older iOS.
- The USB package uses the same bundled Python packages as 1.3.0.
- **Small update package.** `scripts/build_update.sh` (run at the end of
  `build_usb.sh`) copies the full package minus `wheels/`, `install.sh` and
  `run.sh`, and adds `requires/constraints-cp3XX.txt`: the exact versions the
  full package pins. `update.sh` sees `requires/` instead of `wheels/` and runs
  `venv_has_requirements` (in `lib.sh`): every listed package must be installed
  in `/opt/homelib/venv` at that version or newer (newer covers
  `--yt-dlp-online`). Only then does it back up and replace the app; the venv
  is left as is.
